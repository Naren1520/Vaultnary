# Database Schema

## Overview

Vaultnary uses PostgreSQL 16 with 10 SQL migration files (000-009). All tables use UUID primary keys generated by `gen_random_uuid()`. Timestamps use `TIMESTAMPTZ` (UTC). The schema is managed by sqlx-cli and applied via `sqlx migrate run`.

## Table Definitions

### users

Stores registered user accounts.

```sql
CREATE TABLE users (
    id                              UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    email                           TEXT        UNIQUE NOT NULL,
    password_hash                   TEXT        NOT NULL,
    email_verified                  BOOLEAN     NOT NULL DEFAULT false,
    email_verify_token_hash         TEXT,
    email_verify_token_expires_at   TIMESTAMPTZ,
    password_reset_token_hash       TEXT,
    password_reset_token_expires_at TIMESTAMPTZ,
    password_change_required        BOOLEAN     NOT NULL DEFAULT false,
    created_at                      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at                      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_users_email ON users (email);
```

Key points:
- `password_hash` is an Argon2id PHC string — never plaintext
- Token hashes are SHA-256 hex strings; the plaintext token is sent to the user once and never stored
- `password_change_required` is set to true when recovery is used — forces password reset on next login

### auth_sessions

Tracks active login sessions. One row per device/login.

```sql
CREATE TABLE auth_sessions (
    id                  UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id             UUID        NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    token_hash          TEXT        UNIQUE NOT NULL,
    csrf_token_hash     TEXT        NOT NULL,
    ip_address          INET,
    user_agent          TEXT,
    device_fingerprint  TEXT        CHECK (char_length(device_fingerprint) <= 512),
    last_used_at        TIMESTAMPTZ,
    expires_at          TIMESTAMPTZ NOT NULL,
    revoked             BOOLEAN     NOT NULL DEFAULT false,
    created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_auth_sessions_user_id    ON auth_sessions (user_id);
CREATE INDEX idx_auth_sessions_token_hash ON auth_sessions (token_hash);
```

Key points:
- `token_hash` is the SHA-256 hash of the raw session token (stored in the HttpOnly cookie)
- `csrf_token_hash` is the SHA-256 hash of the CSRF token (sent to frontend in login response)
- `device_fingerprint` is optional; supplied by the frontend; max 512 chars; never logged
- `expires_at` is checked on every authenticated request — expired sessions are treated as revoked
- `last_used_at` is updated on every authenticated request by the auth middleware

### vaults

One vault per user. Created automatically on registration.

```sql
CREATE TABLE vaults (
    id          UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    owner_id    UUID        NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    name        TEXT        NOT NULL DEFAULT 'Default Vault',
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE UNIQUE INDEX idx_vaults_owner_id ON vaults (owner_id);
```

Key points:
- UNIQUE constraint on `owner_id` — exactly one vault per user
- Created in the same transaction as user registration

### vault_items

The core credential records. Stores metadata in plaintext and the secret payload as ciphertext.

```sql
CREATE TABLE vault_items (
    id                  UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    vault_id            UUID        NOT NULL REFERENCES vaults(id) ON DELETE CASCADE,
    parent_item_id      UUID        REFERENCES vault_items(id) ON DELETE SET NULL,
    name                TEXT        NOT NULL CHECK (char_length(name) BETWEEN 1 AND 255),
    credential_type     TEXT        NOT NULL CHECK (credential_type IN (
                            'email','website','database','api_key','token',
                            'ssh','service_account','totp','recovery_code','custom'
                        )),
    encrypted_payload   BYTEA,
    payload_metadata    JSONB,
    tags                TEXT[]      NOT NULL DEFAULT '{}',
    notes               TEXT        CHECK (char_length(notes) <= 10000),
    is_favorite         BOOLEAN     NOT NULL DEFAULT false,
    last_accessed_at    TIMESTAMPTZ,
    created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_vault_items_vault_id       ON vault_items (vault_id);
CREATE INDEX idx_vault_items_parent_item_id ON vault_items (parent_item_id);
CREATE INDEX idx_vault_items_last_accessed  ON vault_items (last_accessed_at DESC NULLS LAST);
CREATE INDEX idx_vault_items_tags           ON vault_items USING GIN (tags);
CREATE INDEX idx_vault_items_name_trgm      ON vault_items USING GIN (name gin_trgm_ops);
```

Key points:
- `encrypted_payload` (BYTEA): AES-256-GCM ciphertext — format is `nonce(12) || ciphertext || tag(16)`
- `payload_metadata` (JSONB): non-secret fields for the credential type (e.g. `{"url":"...","username":"..."}`)
- `parent_item_id` self-reference: forms the credential tree; cycle prevention is done in application code via recursive CTE before insert/update
- `tags` TEXT[]: searched via GIN index — fast array containment
- `name` GIN trigram index: supports fast ILIKE substring search
- The API never returns `encrypted_payload` in list or metadata responses

### projects

Software projects that consume credentials.

```sql
CREATE TABLE projects (
    id          UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    owner_id    UUID        NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    name        TEXT        NOT NULL CHECK (char_length(name) BETWEEN 1 AND 100),
    description TEXT        CHECK (char_length(description) <= 500),
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_projects_owner_id ON projects (owner_id);
```

### services

Runtime services within a project (dev/staging/production/custom).

```sql
CREATE TABLE services (
    id          UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    project_id  UUID        REFERENCES projects(id) ON DELETE CASCADE,
    owner_id    UUID        NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    name        TEXT        NOT NULL CHECK (char_length(name) BETWEEN 1 AND 100),
    description TEXT        CHECK (char_length(description) <= 500),
    environment TEXT        NOT NULL CHECK (environment IN ('development','staging','production','custom')),
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_services_project_id ON services (project_id);
CREATE INDEX idx_services_owner_id   ON services (owner_id);
```

### credential_usage

Junction table linking vault items to projects or services.

```sql
CREATE TABLE credential_usage (
    id          UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    item_id     UUID        NOT NULL REFERENCES vault_items(id) ON DELETE CASCADE,
    project_id  UUID        REFERENCES projects(id) ON DELETE CASCADE,
    service_id  UUID        REFERENCES services(id) ON DELETE CASCADE,
    environment TEXT        CHECK (char_length(environment) <= 50),
    notes       TEXT        CHECK (char_length(notes) <= 500),
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    CONSTRAINT chk_usage_target CHECK (project_id IS NOT NULL OR service_id IS NOT NULL)
);
CREATE UNIQUE INDEX idx_credential_usage_item_project
    ON credential_usage (item_id, project_id) WHERE project_id IS NOT NULL;
CREATE UNIQUE INDEX idx_credential_usage_item_service
    ON credential_usage (item_id, service_id) WHERE service_id IS NOT NULL;
```

Key points:
- Either `project_id` or `service_id` must be non-null (CHECK constraint)
- Partial unique indexes prevent duplicate usage records for the same item+project or item+service

### credential_permissions

Tracks who has access to each vault item and at what role.

```sql
CREATE TABLE credential_permissions (
    id          UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    item_id     UUID        NOT NULL REFERENCES vault_items(id) ON DELETE CASCADE,
    user_id     UUID        NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    role        TEXT        NOT NULL CHECK (role IN ('owner','co_owner','editor','viewer')),
    is_favorite BOOLEAN     NOT NULL DEFAULT false,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE UNIQUE INDEX idx_credential_permissions_item_user ON credential_permissions (item_id, user_id);
CREATE INDEX idx_credential_permissions_user_id ON credential_permissions (user_id);
```

Key points:
- One row per (item, user) — UNIQUE enforced
- `is_favorite` is per-user per-item so it lives here rather than on vault_items
- Permission check queries use this table on every vault item request

### share_invitations

Tracks pending, accepted, declined, expired, and revoked sharing invitations.

```sql
CREATE TABLE share_invitations (
    id              UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    item_id         UUID        NOT NULL REFERENCES vault_items(id) ON DELETE CASCADE,
    inviter_id      UUID        NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    invitee_email   TEXT        NOT NULL,
    role            TEXT        NOT NULL CHECK (role IN ('co_owner','editor','viewer')),
    state           TEXT        NOT NULL DEFAULT 'pending'
                                CHECK (state IN ('pending','accepted','declined','expired','revoked')),
    expires_at      TIMESTAMPTZ NOT NULL,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ
);
CREATE INDEX idx_share_invitations_item_state    ON share_invitations (item_id, state);
CREATE INDEX idx_share_invitations_invitee_email ON share_invitations (invitee_email);
```

Key points:
- `invitee_email` not `invitee_id` — the recipient may not have an account yet
- Expiry is enforced lazily at read time (`expires_at < now()`)
- `state` CHECK constraint enforces the valid lifecycle

### credential_key_envelopes

Stores the DEK (data encryption key) for each vault item, encrypted per-user with their RSA public key.

```sql
CREATE TABLE credential_key_envelopes (
    id              UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    item_id         UUID        NOT NULL REFERENCES vault_items(id) ON DELETE CASCADE,
    user_id         UUID        NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    encrypted_dek   BYTEA       NOT NULL,
    key_fingerprint TEXT,
    algorithm       TEXT,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE UNIQUE INDEX idx_key_envelopes_item_user ON credential_key_envelopes (item_id, user_id);
CREATE INDEX idx_key_envelopes_item_id ON credential_key_envelopes (item_id);
```

Key points:
- One row per (item, user) — each user who has access gets their own encrypted copy of the DEK
- `encrypted_dek` is the RSA-OAEP-wrapped raw 32-byte AES key
- When a permission is removed, this row is deleted so the former user cannot decrypt even if they have the ciphertext

### user_public_keys

Stores users' RSA public keys for DEK encryption during sharing.

```sql
CREATE TABLE user_public_keys (
    id          UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id     UUID        NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    public_key  TEXT        NOT NULL,
    fingerprint TEXT        NOT NULL UNIQUE,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_user_public_keys_user_id ON user_public_keys (user_id);
```

Key points:
- Public keys are not secret — readable by any authenticated user via `/api/v1/auth/public-keys/:id`
- Used by the frontend to encrypt DEKs when creating a vault item or sharing one

### recovery_material

Stores the user's encrypted private KEK for account recovery.

```sql
CREATE TABLE recovery_material (
    id                      UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id                 UUID        NOT NULL UNIQUE REFERENCES users(id) ON DELETE CASCADE,
    encrypted_private_key   BYTEA       NOT NULL,
    integrity_tag           BYTEA       NOT NULL,
    kdf_params              JSONB       NOT NULL,
    created_at              TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

Key points:
- UNIQUE on `user_id` — one recovery record per user (upserted on re-setup)
- `encrypted_private_key` is the AES-256-GCM ciphertext of the PKCS#8 private key
- `kdf_params` contains `{ algorithm, memory_cost, time_cost, parallelism, salt }` needed to re-derive the decryption key from the recovery passphrase
- Neither the private key nor the decryption key is ever stored in plaintext

### audit_events

Immutable append-only log of security-relevant actions.

```sql
CREATE TABLE audit_events (
    id              UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    actor_id        UUID        REFERENCES users(id) ON DELETE SET NULL,
    action_type     TEXT        NOT NULL CHECK (action_type IN (
                        'user.registered', 'user.login', 'user.logout',
                        'user.password_changed', 'user.recovery_used',
                        'session.revoked',
                        'item.created', 'item.accessed', 'item.updated',
                        'item.deleted', 'item.exported', 'item.imported',
                        'invitation.created', 'invitation.accepted',
                        'invitation.declined', 'invitation.revoked',
                        'permission.changed'
                    )),
    resource_id     UUID,
    resource_type   TEXT,
    ip_address      INET,
    metadata        JSONB       NOT NULL DEFAULT '{}',
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_audit_events_actor_created ON audit_events (actor_id, created_at DESC);
CREATE INDEX idx_audit_events_action_type   ON audit_events (action_type);
CREATE INDEX idx_audit_events_resource_id   ON audit_events (resource_id);
```

Key points:
- The application database role is granted INSERT and SELECT only — no UPDATE or DELETE
- `metadata` JSONB contains contextual information (IP, user_agent) but never plaintext secrets
- `actor_id` uses SET NULL on user delete to preserve the audit trail after account deletion
- `(actor_id, created_at DESC)` index supports fast per-user timeline queries

## Entity Relationship Summary

```
users
 ├── auth_sessions (1:N)
 ├── vaults (1:1, unique)
 │    └── vault_items (1:N)
 │         ├── vault_items (self-ref, parent_item_id, tree structure)
 │         ├── credential_permissions (N:M via user_id)
 │         ├── credential_key_envelopes (N:M via user_id)
 │         ├── credential_usage (N → projects OR services)
 │         └── share_invitations (1:N)
 ├── projects (1:N)
 │    └── services (1:N)
 ├── user_public_keys (1:N)
 ├── recovery_material (1:1, unique)
 └── audit_events (as actor_id)
```
